## Назначение

`inventory.py` собирает технический паспорт компьютера в JSON, включая IPv4, маску, MAC и рекомендации. `monitor.py` пишет CSV и итоговую статистику CPU, RAM, заполненности диска и времени работы ОС в часах.

Вариант 11: INTERVAL = 2, SAMPLES = 15, пороги CPU/RAM/DISK = 70/90/85%.

## Запуск

Python 3.12 или новее. Из корня репозитория:

```powershell
cd lab1
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe inventory.py
.\.venv\Scripts\python.exe monitor.py
.\.venv\Scripts\python.exe -m unittest -v
```

Для отдельного журнала: `monitor.py --log monitor_baseline.csv`.
На Linux/macOS используйте `.venv/bin/python` вместо `.venv\Scripts\python.exe`.

## Пример формата вывода

Демонстрационные числа, не результаты измерения компьютера:

```text
<время> CPU  10.0% RAM  50.0% DISK  40.0% UPTIME 1.0000 ч
Метрика       Среднее     Максимум     Минимум
cpu             10.000       15.000       5.000
```

Фактические паспорт, журналы и отчёт сформированы локально. Они содержат сведения о рабочей станции и сетевых интерфейсах и пока не опубликованы.

## Правила

Рекомендации: RAM < 8 ГиБ; RAM >= 16 ГиБ и физических ядер >= 6; заполнение диска > 85%; физических ядер < 4. Собственное правило: доступно менее 2 ГиБ RAM.
Порог монитора срабатывает при >=. Дополнительная метрика: `(time.time() - psutil.boot_time()) / 3600`.
Первый вызов `cpu_percent(None)` прогревает счётчик, измерение следует после ожидания.
Скрипт измеряет заполненность диска, а не активность ввода-вывода. Объёмы `_gb` выражены в ГиБ (1024³ байт).

Для опыта в отдельных процессах запускаются `while True: pass` и выделение `bytearray(2*1024**3)`. Выделяйте не более половины общей RAM и убедитесь в наличии свободной памяти. После опыта остановите процессы.
