## Файлы

- `inventory.py` — собирает систему, CPU, RAM, разделы дисков и сетевые интерфейсы IPv4; сохраняет технический паспорт и рекомендации.
- `monitor.py` — выполняет 15 измерений через 2 секунды, проверяет пороги CPU/RAM/DISK 70/90/85%, пишет CSV и среднее, максимум, минимум. Дополнительная метрика — время работы без перезагрузки в часах.
- `passport_waifubook.json` — фактический паспорт компьютера.
- `monitor_log.csv` — фактический эксперимент под нагрузкой; `monitor_baseline.csv` — обычная работа без специально созданной нагрузки.
- `*.summary.json` — сводные показатели соответствующего журнала.
- `experiment_conditions.json` — условия опыта с одним занятым потоком CPU и выделением 2 ГиБ RAM.
- `monitor_load_stdout.txt` — сохранённый вывод монитора под нагрузкой.
- `test_lab.py` — проверки сетевых интерфейсов, рекомендаций, статистики и граничных значений порогов.

## Запуск в Windows PowerShell

Требуется Python 3.12 или новее. Из корня репозитория:

```powershell
cd lab1
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe inventory.py
.\.venv\Scripts\python.exe monitor.py
.\.venv\Scripts\python.exe -m unittest -v
```

Активация окружения не требуется. Для отдельного фонового журнала:

```powershell
.\.venv\Scripts\python.exe monitor.py --log monitor_baseline.csv
```

На Linux/macOS используйте `.venv/bin/python` вместо `.venv\Scripts\python.exe`.
Паспорт и обычный журнал по умолчанию сохраняются рядом со скриптами.

## Опыт с нагрузкой

Запустите монитор, затем в двух отдельных терминалах выполните:

```powershell
.\.venv\Scripts\python.exe -c "while True: pass"
.\.venv\Scripts\python.exe -c "a=bytearray(2*1024**3); input('Enter для освобождения памяти')"
```

После замеров остановите цикл CPU сочетанием Ctrl+C и освободите RAM нажатием Enter.
Для опыта необходимо достаточно свободной памяти; выделяемый объём не должен превышать половину общей RAM.
В выполненном опыте оба процесса были запущены отдельно и автоматически завершены после 15 измерений.

## Особенности реализации

`uptime_hours = (time.time() - psutil.boot_time()) / 3600`.
Первый вызов `cpu_percent(None)` прогревает счётчик; первый замер выполняется после ожидания 2 секунд.
Порог срабатывает при `>=`, рекомендации для занятого диска — строго при `> 85`.
В правиле «RAM ≥ 16 ГБ и ядер ≥ 6» используются физические ядра и доступный системе объём RAM.
На данном ПК установлено 16 ГиБ, но ОС предоставляет 15,73 ГиБ, поэтому это правило не сработало.
Собственное правило — рекомендация закрыть лишние приложения, если доступно менее 2 ГиБ RAM.
Сетевые интерфейсы без IPv4 пропускаются, несколько IPv4 дают несколько записей;
MAC отсутствующего канального адреса записывается как `null`.
Время в результатах содержит смещение `+05:00`; значения с суффиксом `_gb` рассчитаны в ГиБ (1024³ байт).
Частота из `psutil.cpu_freq().max` — значение, сообщаемое ОС, а не максимальная частота Turbo Boost.
